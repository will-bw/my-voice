# C 安全纠错学习

更新日期：2026-09-19

## 观察边界

Auto Learn 仍复用 VoiceInk 的 Accessibility 观察流程，但只在本应用成功投递后启动。一次观察绑定目标进程、目标可编辑控件、投递后的精确 UTF-16 范围和 60 秒窗口；焦点离开、开始下一次录音、自动发送或边界锚点不唯一时结束或放弃。它不会监听其他应用的任意键盘输入。

`FinalSnapshotDiffEngine` 只从本次插入范围的唯一左右锚点恢复局部修订。`CorrectionDiffEngine` 进一步拒绝纯标点、大小写/变音符号风格变化、只增删内容、过长候选和超过 6 个词的整段重写。未通过这些确定性门禁的变化不会进入永久规则流程。

## 人工审核

新安装默认 `Review corrections = Manually`。候选先留在本地队列；用户选择 “Review Now” 后，AI 只做建议分类，结果进入人工审核面板，不直接写入词库。

人工审核明确区分四种结果：

| 选择 | 持久化效果 |
|---|---|
| Replacement + Vocabulary | 新增替换来源并加入标准词 |
| Replacement only | 只新增替换来源 |
| Vocabulary only | 只加入标准词 |
| Dismiss / reject | 不创建规则，记录负反馈 |

用户仍可显式选择 `Immediately`，但这不再是默认值。

## 反馈、撤销与停用

`CorrectionFeedbackMetadata` 是本地侧表，以规范化的“来源词 → 目标词”唯一键保存接受、拒绝、Undo、用户改回、置信度和启用状态。迁移只为已有 `WordReplacement` 变体补建元数据，不修改可见规则内容；孤儿元数据保留并计数，防止删除规则后立刻忘记负反馈。

- 人工接受会提升对应纠错和目标词的正反馈；
- Dismiss、Undo 和精确改回会降低置信度；
- 两次负反馈会停用该具体来源/目标对；
- `WordReplacementService` 在应用前读取侧表，不再执行已停用的具体变体；
- 只有当“把目标词替换回来源词”能精确重建整个局部修订时，才记录用户改回，普通润色不会被误判为改回。

## 模型对照边界

SenseVoice Small 继续作为默认本地模型。SenseVoice 与 Whisper Large v3 Turbo Quantized 的结论必须来自同一批个人真实录音；当前没有用户提供的 100 条语料和量化 Whisper 模型结果，因此不改变默认值，也不伪造对照数据。检查点 D 的评测工具会使用同一 manifest 对两个本地模型记录 CER、实体指标、最终修改率和延迟。

## 自动化验证

`AutoLearnSafetyTests` 覆盖：

- 新安装默认人工审核；
- 纯标点、大小写和整句重写门禁；
- 局部专业词纠错仍可进入候选；
- 重复锚点时放弃范围恢复；
- 四类审核选择产生不同持久化结果；
- 侧表幂等迁移且不改写已有规则；
- 接受、Undo、拒绝和用户改回更新反馈；
- 两次负反馈后具体规则停止应用。

真实跨应用人工审核仍需要用户产生一条新的个人纠错样例；本地模型优劣对照仍需要个人语料。
